# Lyrinotch

[English](README.md) | [繁體中文](README.zh-Hant.md) | [简体中文](README.zh-Hans.md) | [日本語](README.ja.md)

<!-- section: overview -->

Spotify と Apple Music 向けに、同期歌詞を MacBook のノッチ付近、またはその他のディスプレイ上のフローティングカードに表示する、非公式のサードパーティ製 macOS メニューバーアプリです。

> **Lyrinotch は Spotify、Apple、Apple Music、LRCLIB、その他いかなる歌詞プロバイダーとも提携しておらず、承認、後援、推奨を受けていません。**

|---|---|
| **現在のソースバージョン** | 1.0.1 (build 1) |
| **プラットフォーム** | macOS 14 以降。Apple Silicon 推奨 |
| **プレイヤー** | Spotify デスクトップアプリおよび／または Music.app |
| **インターフェース言語** | 英語、繁体字中国語、簡体字中国語、日本語、および「システムに従う（Follow System）」 |
| **ライセンス** | [MIT](LICENSE) |
| **リポジトリ** | [github.com/barrygg11/lyrinotch](https://github.com/barrygg11/lyrinotch) |

ソースツリーのバージョンは、GitHub でダウンロードできる最新成果物より新しい場合があります。各成果物のバージョン、署名、ノータリゼーションの状況は、[Releases ページ](https://github.com/barrygg11/lyrinotch/releases)で確認してください。

## 主な機能

### あらゆるディスプレイに対応する歌詞表示

- **ノッチ搭載 MacBook：** 折りたたみ時のアイランドに、カメラハウジングの下へ現在の歌詞を表示します。ポインタを合わせるか展開すると、より多くの歌詞と操作項目を表示できます。
- **その他のディスプレイ：** メニューバーの下にフローティングカードを表示します。
- マウスに追従させる、メインディスプレイを使う、または特定の画面にオーバーレイを固定することができます。
- 必要に応じて、フルスクリーン時の非表示、クリック透過、レイアウト調整、展開時の表示形式を設定できます。

### 操作を邪魔しない再生連携

- ローカルの AppleScript Automation を通じて、曲名、アーティスト、アルバム、再生時間、再生位置、アートワーク、再生状態を読み取ります。
- 「自動」「Spotify を優先」「Apple Music を優先」に対応し、優先プレイヤーが再生していない場合は自動的に切り替えます。
- 展開したオーバーレイから、前の曲、再生／一時停止、次の曲、シーク／進捗、歌詞タイミングのクイック調整を操作できます。
- 設定可能なグローバルホットキーに対応し、パッケージ化されたアプリではログイン時起動も利用できます。

### 外観とアクセシビリティ

- ライブプレビューを見ながら、歌詞サイズ、表示面の不透明度、アートワーク由来の色、間隔、垂直位置、ディスプレイ動作を調整できます。
- 実行中の macOS が対応している場合、ノッチアイランドとフローティングカードの Liquid Glass を個別に設定できます。
- 設定画面と表示テキストには、選択したインターフェース言語が反映されます。
- 一時停止中も操作項目を表示し続けるため、オーバーレイから再生を再開できます。

## 歌詞、翻訳、タイミング

### 歌詞ソース

| ソース | ネットワーク？ | 備考 |
|--------|----------|-------|
| LRCLIB | はい | 新規インストール時の既定のプロバイダー設定です。 |
| NetEase / lyrics.ovh | はい | 選択したプロバイダー設定で有効になっている場合にのみ使用します。 |
| Music.app 埋め込み歌詞 | ローカル | 設定された取得パイプラインでローカルの Music ソースが許可されている場合に照会します。 |
| ローカル `.lrc` インポート | ローカル | ファイルを明示的に選択します。UTF-8 および BOM 付き UTF-16 に対応し、上限は 1 MB です。 |
| Tap Sync | ローカル | 曲の再生中に歌詞行のアンカーを記録し、後からプロジェクトを再開できます。 |

プロバイダー設定は、自動検索と手動検索の両方に適用されます。Lyrinotch は Spotify Web や Apple Music Web をスクレイピングせず、このリポジトリに著作権で保護された `.lrc` ファイルを同梱しません。

### 同期歌詞が見つからない場合の復旧手段

- 通常歌詞、タイミング付き行の不足、再生範囲内のタイミング行不足を、単一の汎用的な校正失敗ではなく、それぞれ異なる状態として報告します。
- 信頼できる版の LRC がある場合は、それをインポートできます。
- **Tap Sync** を使用すると、曲を一度再生しながら各行の位置を記録できます。実際にタップした位置はそのまま保持され、行間、イントロ、アウトロは、隣接するアンカーと元の歌詞の間隔から推定されます。
- Tap Sync の下書き、取り消し履歴、ソースフィンガープリント、生成済みタイムラインは、インポート元ファイルのパスを保持せずに、アプリの再起動後も復元できます。

### 翻訳

任意機能の翻訳は、MyMemory を通じて繁体字中国語、簡体字中国語、英語、日本語に対応します。翻訳元言語は MyMemory が推定し、翻訳先言語はユーザーが選択します。次の行をあらかじめ用意できるよう、現在行と次行の歌詞が、推定された翻訳元言語およびユーザーが選択した翻訳先言語とともに送信される場合があります。

### タイミング補正

- 現在の環境に対する歌詞全体のオフセットを設定できます。
- 現在の曲を ±0.5 秒刻みで調整する、次の行を即座に現在位置へ合わせる、またはその曲の補正を消去することができます。
- 任意機能のマイク校正は**既定でオフ**で、スピーカー再生向けです。歌詞のタイムスタンプと、端末内で縮約したオンセット／エネルギー包絡線を比較します。
- 校正には、利用可能な同期歌詞ポイントと安定した再生が必要です。曖昧なサンプル、境界付近のサンプル、中断されたサンプル、出力経路変更後のサンプル、古くなったサンプルは保存せず拒否します。
- 補正値は、プレイヤー、曲の識別情報、歌詞タイムライン、オーディオ環境ごとに分離されます。

## 権限とトラブルシューティング

### Automation

Lyrinotch が読み取りまたは操作する各プレイヤーには、Automation のアクセス許可が必要です。

1. 先に Apple Music および／または Spotify を起動します。
2. **Lyrinotch 設定 → プレイヤー**を開きます。
3. プレイヤーごとに**「アクセス許可を確認」**を選ぶか、**「すべてのアクセス許可を確認」**で順番に確認します。
4. macOS の同意確認が表示された場合は応答します。

アプリは、**許可済み**、**未許可**、**拒否**、**プレイヤーが起動していません**、**確認がタイムアウトしました**、**未確認**を区別します。「プレイヤーが起動していません」は権限の拒否ではありません。そのプレイヤーを起動してから、もう一度確認してください。アクセスを拒否した場合は、**システム設定 → プライバシーとセキュリティ → オートメーション**で Lyrinotch を許可し、アプリ内でもう一度確認してください。

アプリの署名を変更した場合や、別の方法でパッケージ化されたコピーを実行した場合、macOS が別の Automation クライアントとして扱うことがあります。通常の利用では、インストール済みで一貫した署名を持つ単一のアプリを使用してください。

### マイク

マイクの権限を要求するのは、歌詞の自動校正を有効にした後、またはスピーカーからのフィードバックを利用できる手動再校正を開始した後だけです。マイクを無効のままにして、LRC インポート、Tap Sync、手動オフセットを使用することもできます。

## プライバシーとデータフロー

Lyrinotch は完全にローカルな歌詞ソースも利用できますが、オンラインプロバイダーへの照会、翻訳、リモートアートワーク、更新確認にはネットワークアクセスが必要です。

| 処理 | ローカル／ネットワーク | Mac の外部へ送信される可能性があるもの |
|----------|-----------------|-------------------------|
| 再生中情報の読み取り、再生、一時停止、スキップ、シーク | ローカルの Automation | なし。Apple Event は、この Mac 上のプレイヤーアプリにのみ送信されます。 |
| 歌詞の取得または検索 | 有効なプロバイダーではネットワーク。ローカルの Music.app 照会は任意 | 曲を特定するために必要な曲名、アーティスト、再生時間、アルバム、関連する検索メタデータ。 |
| 歌詞の翻訳 | ネットワーク。MyMemory の任意機能 | 現在行と次行の歌詞、推定された翻訳元言語、およびユーザーが選択した翻訳先言語。 |
| アルバムアートワークの読み込み | ローカルおよび／またはネットワーク | プレイヤーが HTTPS のアートワーク URL を提供した場合のリモート画像リクエスト。 |
| マイクによるタイミング校正 | ローカル。任意 | マイク音声はアップロードされません。10～18 秒の処理中にメモリ上でオンセット／エネルギー包絡線へ縮約され、生のサンプルはディスクへ書き込まれません。 |
| LRC のインポートまたは Tap Sync の使用 | ローカル | なし。解析済みタイムライン、アンカー、取り消し履歴、曲の識別情報、歌詞フィンガープリントがローカルに保存される場合があります。元ファイルのパスは保持されません。 |
| 更新の確認 | ネットワーク、GitHub | アプリのバージョンと標準的な HTTP リクエストメタデータ。 |
| Spotify / Apple アカウントへのログイン | 未使用 | Lyrinotch は Spotify または Apple の OAuth トークンを保存しません。 |
| アナリティクス、広告、独自テレメトリ | なし | Lyrinotch はユーザー追跡用バックエンドを運用しません。 |

ローカルに保存されるデータには、設定、選択した歌詞、プロバイダーキャッシュ、アートワークキャッシュ、翻訳キャッシュ、曲ごとのオフセット、校正の信頼度／環境フィンガープリント、Tap Sync プロジェクトが含まれる場合があります。**選択した歌詞と曲別補正を消去…**を実行すると、手動選択した歌詞、曲別タイミング補正、Tap Sync の下書きと取り消し履歴、およびメモリキャッシュが削除されます。その他の設定は保持されます。

セキュリティ報告ポリシーとローカル処理に関する詳細な方針については、[SECURITY.md](SECURITY.md)を参照してください。

## パッケージ版のインストール

[GitHub Releases](https://github.com/barrygg11/lyrinotch/releases)で適切な成果物が公開されている場合：

1. リリースノートと署名／ノータリゼーションの状況を確認します。
2. DMG を開きます。
3. **Lyrinotch.app** を **Applications** にドラッグし、必要に応じて古いコピーを置き換えます。
4. インストールしたアプリを起動します。ノータライズされていないローカルビルドは、初回起動時に**右クリック → 開く**が必要な場合があります。
5. 使用するプレイヤーを起動し、**設定 → プレイヤー**で Automation の権限を確認します。

ログイン時起動は、パッケージ化された `.app` で安定して動作します。`swift run` セッションでの使用は想定していません。

### 動作要件

- macOS 14 以降
- Spotify および／または Music (Apple Music) デスクトップアプリ
- 使用する各プレイヤーの Automation 権限
- スピーカーを使ったタイミング校正を行う場合は、任意のマイク権限
- ソースからビルドする場合は、Xcode 16 以降または Swift 5.10 以降のツールチェーン

## ソースからのビルドと実行

```bash
git clone https://github.com/barrygg11/lyrinotch.git
cd lyrinotch

swift build
swift test

# メニューバーアプリ + オーバーレイ。ターミナルセッションを開いたままにしてください。
swift run Lyrinotch

# CLI の診断／ポーリングモード。
swift run Lyrinotch --cli
swift run Lyrinotch --once
swift run Lyrinotch --cli --interval-ms 1000
swift run Lyrinotch --help
```

ローカルでダブルクリック可能なアプリまたはディスクイメージを作成するには：

```bash
./scripts/package-app.sh
open dist/Lyrinotch.app

./scripts/create-dmg.sh --local
```

生成されたアプリ、DMG、チェックサム、Swift のビルド生成物は、`.gitignore` により Git の管理対象外となります。

## 署名と配布モード

| モード | 用途 | 重要な動作 |
|------|--------------|--------------------|
| Ad-hoc（既定） | ローカルのソースビルド | ノータライズされません。更新は手動でインストールします。識別情報が変わると、macOS が権限を再度要求する場合があります。 |
| Apple Development | 許可された開発用 Mac での安定したテスト | 識別可能なローカルビルドですが、一般配布版でもノータライズ済みリリースでもありません。 |
| Developer ID Application | 一般配布 | クリーンなタグ、hardened runtime、タイムスタンプ、ノータリゼーション、ステープル、完全性検証、チェックサムの手順に従う必要があります。 |

ローカルの Apple Development ビルド例です。自身の Keychain とデベロッパーアカウントの値を使用してください：

```bash
security find-identity -v -p codesigning

export SIGN_IDENTITY="Apple Development: Your Name (CERTIFICATE_ID)"
export UPDATE_TEAM_ID="YOURTEAMID"
export DMG_SIGN_IDENTITY="$SIGN_IDENTITY"
./scripts/create-dmg.sh --local
```

生成されたローカル DMG を公式リリースとして公開しないでください。Developer ID 成果物を準備するメンテナーは、バージョン／タグの確認、コード署名、ノータリゼーション、ステープル、マウント済み DMG の検証、SHA-256 の生成、リリース検証を扱う [docs/releasing.md](docs/releasing.md) に従う必要があります。

アプリ内アップデーターが自動置換を提供するのは、実行中のアプリに信頼済み Team ID が埋め込まれている場合だけです。置換前に、リポジトリのリリース URL、任意の GitHub SHA-256 ダイジェスト、bundle identifier、バージョン、コード署名、Team ID を検証し、ロールバック可能な状態で置換を準備します。

## 検証

CI は、多言語ドキュメントとリリースノート、厳格な Swift concurrency、最適化された Release ビルド、コードカバレッジ付きテスト、本番ソースの行カバレッジ下限 25% を検証します。

```bash
bash scripts/check-readme-sync.sh
bash scripts/test-release-notes-checker.sh
bash scripts/check-release-notes.sh

swift test --enable-code-coverage \
  -Xswiftc -strict-concurrency=complete \
  -Xswiftc -warn-concurrency \
  -Xswiftc -warnings-as-errors

bash scripts/check-coverage.sh 25
swift build -c release
```

README チェッカーは、4 言語すべてでリビジョン／バージョンマーカーとセクション順が一致していることを求め、参照先が存在しないローカル Markdown リンクを拒否します。
